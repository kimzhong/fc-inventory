# Changelog

All notable changes to `fc-inventory` are documented here. The format is
based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the
project adheres to [Semantic Versioning](https://semver.org/).

## [3.0.0] - 2026-06-06

### Changed — breaking

- **Complete rewrite to FastAPI.** The v1.0.0 Python + Flask implementation
  is replaced by an async FastAPI service. The Flask layer,
  `waitress` WSGI server, and `threading.Thread` background workers are
  gone.
- **Async httpx replaces sync `requests`.** The FC client is now
  `async`; resource fetches within a site run concurrently via
  `asyncio.gather` (clusters + hosts + datastores + dvswitches, then
  host details in parallel, then VM details in parallel).
- **Pydantic models with `SecretStr` password.** `CollectRequest.password`
  is `pydantic.SecretStr`; the cleartext never reaches logs, repr, or
  the OpenAPI echo.
- **`POST /api/collect` response shape changed** — now returns
  `{"status": "started", "job_id": "..."}` (v1.0.0 returned only
  `{"status": "started"}`). The `job_id` is opaque and used for
  correlation.
- **New endpoints:** `GET /api/health` (k8s-friendly), `GET /docs`
  (Swagger UI), `GET /redoc` (ReDoc), `GET /openapi.json`. All auto-
  generated by FastAPI.
- **Configuration via `pydantic-settings`.** All knobs come from env
  vars prefixed `FC_INVENTORY_` (10 settings, see `.env.example`).
  The two v1.0.0 settings (`FC_INVENTORY_BIND`, `FC_INVENTORY_PORT`)
  are preserved for backward compatibility.
- **Production server is `uvicorn`** instead of `waitress` (async-
  native; `uvloop` for free speedup).
- **Structlog replaces stdlib `logging`.** Same rotating file
  configuration (5 MB × 3 backups, 30-day retention, gzip) but
  structured key-value output that survives log-aggregator parsing.
- **Hybrid field mapping preserved verbatim.** The 8 `*_FIELDS` tables
  and the path-walking helpers are a 1:1 port of `collector.py:21-230`
  so the `.xlsx` output is functionally identical to v1.0.0.
- **Login matrix preserved verbatim.** Same 6 versions, same 3 auth
  methods, same 3 ports, same `"10000022"` body check, same
  connection-error break semantics.
- **Excel styling preserved.** Same `#2C3E50` bold-white header,
  autofilter, freeze row 1, autosize from first 100 rows capped at 50.
- **Per-VM disk/NIC fallback chain preserved.** `disks -> volumes ->
  /volumes -> /disks` for disks; inline `vmConfig.nics` for NICs.
- **Site-level portgroup fallback preserved.**

### Added

- **Test suite: 90 tests, pytest + httpx MockTransport.**
  - `test_fc_client.py` — login matrix, pagination, fallback chain,
    URL stitching, TLS-verify-disabled assertion, token extraction
    from header / body.
  - `test_field_map.py` — golden tests for the 8 mapping tables,
    prettify key, fallback, extras passthrough.
  - `test_collector.py` — 10 sheet builders, MB→GB conversion,
    cancellation, concurrent fetch path.
  - `test_jobs.py` — `JobManager` state machine, atomic `try_start`,
    `JobAlreadyRunning` exception, concurrent cancel + collect.
  - `test_excel_builder.py` — round-trip via `openpyxl.load_workbook`,
    header style, freeze, autofilter, autosize cap 50, empty-sheet
    placeholder.
  - `test_api.py` — end-to-end via `TestClient`: collect → progress
    poll → download, 409 on concurrent collect, 400 on missing field,
    health, version, changelog.
  - `test_settings.py` — env-var interpolation, defaults, invalid
    port, CORS CSV parsing.
- **Modern packaging:** `pyproject.toml` (PEP 621), `setuptools`
  build backend, `twine`-ready wheel + sdist.
- **Multi-stage Dockerfile** (python:3.12-slim), non-root `fcuser`,
  multi-arch build (linux/amd64, linux/arm64), healthcheck via
  `/api/health`.
- **Makefile** with `install`, `run`, `lint`, `type`, `test`, `cov`,
  `docker`, `build`, `clean` targets.
- **Ruff + mypy** in the dev toolchain (`pyproject.toml` config).
- **Async `attach()` helper** on `InventoryCollector` so the route
  handlers don't reach into `collector.client` directly.
- **Aggregated SHA-256 checksums** in the release pipeline (mirrors
  the fix the Go branch landed at `30bf9d3`).

### Removed

- `waitress` (WSGI server) — replaced by `uvicorn`.
- `flask` — replaced by FastAPI.
- `requests` — replaced by `httpx`.
- The `threading.Thread` background worker in v1.0.0's `app.py:51-55`
  is replaced by FastAPI's `BackgroundTasks`.
- The hand-rolled `current_job` global dict is replaced by a typed
  `Job` dataclass + `JobManager` singleton (`asyncio.Lock`-protected).

### Security

- Password never reaches the log sink: `pydantic.SecretStr` plus the
  `KeyValueRenderer`-based structlog config (which never sees
  `password.get_secret_value()`).
- No open ports by default: `FC_INVENTORY_BIND=127.0.0.1`.
- No telemetry: the only outbound connection is to the configured
  FC VRM.

## [2.0.0 / 2.0.1] - 2026-06-06

A Go rewrite on `feat/golang-rewrite` (not merged). Dropped the web
layer entirely; YAML config instead of per-request JSON. The release
artifacts are still on the v2.0.0 / v2.0.1 tags. **This direction was
not adopted** — v3.0.0 returns to Python + FastAPI while keeping the
web UI. The Go branch remains in git history as reference.

## [1.0.0] - 2026-04-10

Initial public release. Python 3 + Flask + waitress + openpyxl. See
git history prior to the v3.0.0 commit for the v1.0.0 source.
